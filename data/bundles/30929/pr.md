#### Brief description of what is fixed or changed

`Dummy.__new__` stored `dummy_index` as given. `srepr` writes it as a bare integer, but `parse_expr`/`sympify` runs `auto_number`, which turns that integer into a SymPy `Integer`. `Basic.__eq__` compares hashable content items strictly by number type, so the recreated `Dummy` was not equal to the original one:

```python
>>> d = Dummy('d', dummy_index=5)
>>> sympify(srepr(d + 1)) == d + 1
False
>>> sympify(srepr(CRootOf(x**3 - x + 1, 0)))
PolynomialError: only univariate polynomials are allowed
```

In the second case the two occurrences of the same `Dummy` inside the polynomial become two separate generators.

The change normalizes `dummy_index` to `int` in `Dummy.__new__`, so the stored value does not depend on whether it arrives as a Python integer or as a SymPy `Integer`.
